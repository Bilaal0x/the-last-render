# The Last Render

A 12-second film (1920×1080, 30 fps) that travels backward through its own existence.
It starts as a finished frame. That frame comes apart into the GPU draw calls that drew it,
then into the SVG tree behind those calls, then into the Rust source that built the tree,
and finally into one blinking cursor. There are no cuts: the camera keeps pulling back the
whole time.

Built with [fframes](https://github.com/dmtrKovalenko/fframes) 1.2. There is no stock
footage, no audio file, and no browser anywhere in the pipeline: every pixel and every
sample is generated by the code in this repository.

| seconds    | layer      | what you see                                                         | what you hear                          |
| ---------- | ---------- | -------------------------------------------------------------------- | -------------------------------------- |
| 0.0 – 3.0  | `Beauty`   | a neon city at the horizon, rendered live as SVG                     | sub-bass, warm detuned pad             |
| 3.0 – 5.5  | `Commands` | the frame splits into triangles, one draw call at a time             | a metallic, glassy ping per draw call  |
| 5.5 – 8.0  | `SvgTree`  | every SVG element lifts to the plane of its tree depth               | soft digital clicks, a data stream     |
| 8.0 – 10.5 | `Source`   | the code that drew the frame is typed back, `svgr!` calls expanding  | pure sine tones, soft key clicks       |
| 10.5 – 12  | `Cursor`   | everything collapses into a cursor on black                          | one soft click, then silence           |

## Run it

```bash
tools/render.sh                      # -> out/the-last-render.mp4 (360 frames, 12.000 s)
```

The script builds the project and runs `timeline`, `inspect --fail-on warning` and
`audio analyze`. It then renders and checks with `ffprobe` that the file has exactly 360
frames at 1920×1080. On this machine (RTX 3070, Vulkan) the render takes about 45 s.

Every other command goes through the same binary. It writes the passes first, then hands
over to the fframes CLI:

```bash
cargo run --release -- preview 0s          # real-time window with sound (Vulkan; Metal on macOS)
cargo run --release -- preview 5.5s        # start at the SvgTree layer
cargo run --release -- strip all -n 24     # contact sheet -> strip.png
cargo run --release -- strip Commands -n 12
cargo run --release -- frame 3.6s,SvgTree@50%,Cursor@end -o out/frames
cargo run --release -- inspect
cargo run --release -- audio analyze --waveform out/waveform.png
cargo run --release -p sfx                 # re-synthesize out/passes/score.wav from out/tracks.json
```

The five layers are registered as scenes, so the CLI can address them by name
(`Beauty`, `Commands`, `SvgTree`, `Source`, `Cursor`). The scenes themselves draw nothing:
each frame is composed from the global second, so the transitions have no seams.

### Requirements

- Rust 1.95+.
- The FFmpeg libraries that fframes links. On Windows that means a shared FFmpeg build with
  `FFMPEG_DIR` set, its `bin` on `PATH`, and `LIBCLANG_PATH` pointing at LLVM. See the
  fframes README.
- A GPU with Vulkan (Linux/Windows) or Metal (macOS). The backend is chosen with `cfg` in
  `composite/Cargo.toml` and `composite/src/main.rs`. Only the Vulkan path has been built
  and run so far.

## How it is built

```
the-last-render/
├── hud/         shared: SceneLayer, Timeline, Camera, NodeRecord, schedule, Tracks (tracks.json)
├── beauty/      pass 1: the city as data (scene.rs) -> SVG, NodeRecords, a one-frame still video
├── commands/    pass 2: shaders/pipeline.sksl (the one shader, four modes) + the draw-call list
├── svg_tree/    pass 3: every NodeRecord floating in 3-D, with real matrices, boxes and edges
├── source/      pass 4: beauty/src/scene.rs typed back, svgr! calls expanding; the final cursor
├── composite/   the fframes Video: camera, layer blending, aberration, grain, CLI (main.rs)
├── tools/
│   ├── render.sh    one command -> out/the-last-render.mp4
│   └── sfx/         pure-Rust synthesizer (lib + `sfx` binary) reading tracks.json
└── out/         generated: tracks.json, passes/beauty.png, passes/score.wav, the film
```

### The passes, in order

`composite/src/main.rs` runs these steps on every start, before the CLI:

1. **`out/tracks.json`.** `hud::Tracks::build` takes the `NodeRecord` of every element in the
   beauty pass and the size of the source text. It writes:
   - one entry per frame, holding the layer, the continuous depth (0–5), the layer weights,
     the full camera, and the synth controls;
   - every discrete event (draw call, node reveal, keystroke, cursor click), with its second,
     pitch, pan, gain and cutoff.
2. **`out/passes/beauty.png`.** `beauty::BeautyStill` is a one-frame fframes `Video`. It is
   rasterized through fframes' `Previewer` at the second the dissolve begins (3.0 s), at half
   size.
3. **`out/passes/score.wav`.** `sfx` reads `tracks.json` back from disk and synthesizes 48 kHz
   stereo.
4. `out/passes` is loaded as a runtime `MediaDirectory` (stereo audio, the baked image), and
   the fframes CLI takes over.

Why the beauty pass is baked: in fframes 1.2 a shader's `uniform shader` child can only be
bound to a raster image (`ShaderUniforms::image`). A live `Shader::draw` result can't feed
another shader, and neither can an SVG subtree. So pass 1 is rendered to pixels first, and
the SkSL pipeline reads it as `iChannel0`, just as a multi-pass renderer reads its previous
target.

### Data structures (`hud`)

- `SceneLayer` is `Beauty | Commands | SvgTree | Source | Cursor`.
- `Timeline` holds `marks: [0.0, 3.0, 5.5, 8.0, 10.5, 12.0]` and the dissolve length into
  each layer. It provides `weight(layer, t)`, `depth(t)` and `progress(layer, t)`.
- `NodeRecord` exists for every SVG element. It stores:
  - `bbox`, the original bounding box in frame pixels;
  - `transform`, the accumulated matrix from the root;
  - `path_hash`, FNV-1a 64 of the exact `d` string that is rendered;
  - `depth` in the tree;
  - plus `id`, `parent`, `tag`, `name`, `paint` and `segments`.
- `Camera::at(t)` is a pinhole camera.
  - It moves along a monotone cubic through `DOLLY_KEYS`, so it never stops and never moves
    forward. A slow lateral drift fades out before the cursor lands.
  - Focus follows the active layer's plane. The aperture opens with pipeline depth (soft
    depth of field that deepens as we dig).
  - `aberration` and `grain` ramp up toward the end, then drop to zero for the clean black
    finish.

Space is measured in pixels of the finished frame. The beauty frame is the plane z = 0, and
each later stage floats on planes closer to the viewer (`hud::camera`). The camera pulls
back through them, so each new layer arrives in front of the last one.

### The shader (`commands/shaders/pipeline.sksl`)

One SkSL program, drawn twice per frame:

- **`uMode.x`, beauty reconstruction.** Ray–plane intersection with the baked frame. A
  9-tap disc blur sized from the circle of confusion gives the depth of field, and a cyan
  border appears once the frame is far enough away to read as an object.
- **`uMode.y`, command buffer.** The frame is cut into triangles in six slices that lift
  toward the camera. Draw order follows the raster. Each triangle goes from shaded, to a flat
  draw-call fill, to wireframe, and fragment invocations flicker as the scan front passes.
- **`uMode.z`, wireframe tree.** The empty depth planes of the tree, as outlines and dot
  lattices.
- **`uMode.w`, source particles.** 3×5 bitmap glyphs drifting through a slab around the
  source plane, tinted by the frame they came from.
- **`uPost = 1`.** The same file draws film grain and the vignette over everything.

Chromatic aberration is applied twice:

- inside the shader, by evaluating the scene three times with radial offsets;
- on the vector layers, by an SVG channel-split filter in `composite`.

### Everything on screen is real

- The draw-call list shows the actual drawable nodes in document order, with their
  path-hash prefixes. The highlighted box is that node's real `bbox` (clipped to the
  canvas), projected through the camera.
- The tree labels show each group's real accumulated matrix. The spotlight panel shows the
  last node to detach: its box, matrix, full path hash, depth, segment count, and the second
  it left the frame.
- The source text is `include_str!("scene.rs")`, the region between the
  `the-last-render:source` markers, with its real line numbers. The `svgr!` expansions show
  what the renderer emits for real nodes, including the window flicker opacity at that
  exact frame.
- `t=…s` and `draws n/61` are the frame's own time and draw count.

### Sound from the same data

`tools/sfx` reads only `tracks.json`.

- **Beds** follow the per-frame `AudioControls`, interpolated to the sample:
  - pad gain and a low-pass cutoff that closes as camera distance grows;
  - a crystalline shimmer;
  - a stream band-pass whose centre follows the camera;
  - sine pitch falling an octave as the source collapses;
  - stereo pan following the camera's drift.
- **Events** are placed at their exact seconds.
  - Draw calls are FM bells with an inharmonic modulator. Pitch comes from the path hash on
    an E pentatonic, pan from the box's x, gain from the box's area.
  - Node reveals are noise-burst clicks, pitched by depth.
  - Keystrokes are soft ticks over a low thock.
  - The cursor gets one click. The reverb tail is gated shut 0.75 s after it, so the film
    ends in true silence.

The mix is levelled by RMS and soft-limited. Current measurement: −15.7 LUFS integrated,
−3.7 dBTP true peak, no clipped samples.
